(A) THE HEADLINE IS THE STRATIFICATION, AND IT WAS REGISTERED IN ADVANCE.
      class            compiled after one retry
      UNUSED VAR                 1/1
      TYPE/SEMANTIC              4/11    36%
      TRUNCATED (8000 tokens)    1/3
      PARSE                      0/1
      INVENTED SYMBOL            0/7      0%
  P(INVENTED converts at a LOWER rate than TYPE/SEMANTIC) = 0.55 -> HIT, and the registered reason
  is the finding itself: "undefined: X" tells the model its symbol is wrong and NOT what the right
  one is, while a type error names the type it should have used. Zero of seven against four of
  eleven is that sentence with a number under it.
  A compile error is not one signal. It is two: a TYPE error is information the model can act on,
  and a NAME error is the model's ignorance of the package reflected back at it in a machine-readable
  coat. Feeding it back teaches nothing, because the package is what it does not know.

(D) TRUNCATION IS NOT ONLY A CEILING. Doubling the budget to 8000 tokens converted 1 of 3. The other
  two produced another long file and ran out again. For those rows the model is not being cut short
  of a finish; it is writing something that has no finish. That is a different defect from the
  no-test class, where a single sentence of feedback converted 16/16, and it says the ceiling
  hypothesis is dead in both directions: tokens were not the cause there, and they are not the cure
  here.

FINDINGS:
  1. The compiler is a usable teacher for TYPES and is useless for NAMES. 4/11 against 0/7. Any future
     loop that feeds toolchain errors to a writer should expect nothing from the undefined-symbol
     class, and the archive should stop counting "nocompile" as one number.
  2. The invented-symbol class is a RETRIEVAL problem, not a training problem, and the exemplar arm
     already proved retrieval works on this writer. The indicated cheap step is to put the package's
     actual exported symbols in front of the writer, which is the same lever that moved USEFUL from
     2 to 4, aimed at the exact rows where it is still blind.
  3. Across three arms today: USEFUL 2 -> 4 -> 5, ROUTER 17 -> 18 -> 18, nocompile 21 -> 23 -> 17,
     toothless 10 -> 6 -> 8. Everything that moved USEFUL was RETRIEVAL. Everything that was a
     deterministic repair or a retry moved the shape of the failures and not the count of the wins,
     with one exception worth one test.
  4. Twenty false alarms are now the largest class on the bench and no instrument in this line can
     see them. A test red at the parent and red on the gold is indistinguishable at run time from a
     test with teeth; only the gold separates them, and the router never has it. That is the ceiling
     of the whole self-test idea as currently built, and it is not a writer problem.
